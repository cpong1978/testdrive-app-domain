Privacy policy

How testDrive accesses, uses, stores and shares information.

Effective date: 5 November 2026

1. Operator and scope

testDrive is a personal Windows desktop setup operated by cpong1978, using Rclone to connect an authorized Google Drive account. The operator's contact email is cpong1978@gmail.com. This policy covers that setup and this public informational website.

The setup currently has no public registration or multi-user file-sharing portal.

2. Information accessed

With the account owner's Google OAuth consent, the desktop setup can access file and folder names, identifiers, hierarchy, sizes, modification times, available checksums and file contents. The configured full Drive scope can permit reading, creating, updating, moving and deleting files across the authorized account, subject to Google's permissions and API limitations.

OAuth access and refresh tokens are used to maintain the authorized connection. The setup does not receive or store the account's Google password.

3. Purpose and use

Drive data is used to display folders, open and download files, cache content locally, and carry out upload, update, move or delete operations requested by the operator or applications using the mounted drive. Operational logs may include file paths, transfer status and errors for troubleshooting.

Google user data is not sold, used for advertising or used to train AI models. It is used for the file-access functions described here, consistent with the Google API Services User Data Policy, including its Limited Use requirements.

4. Storage and retention

Cloud files remain in Google Drive. OAuth tokens, Rclone configuration, operational logs and cached file contents are stored on the operator's computer. Access to the configuration and cache directories is restricted through Windows file permissions.

The current cache is configured to target 10 GiB and remove eligible unused content after 12 hours. These are cleanup targets, not guarantees: open files, pending uploads or stopped services can leave data for longer. Current mount logs rotate at 10 MiB with up to three backups and a seven-day retention setting. Credentials remain until removed or replaced. Files intentionally copied elsewhere are not removed by cache cleanup.

This public website does not store OAuth credentials or host the operator's Drive files.

5. Sharing and service providers

File requests and authorized changes are exchanged with Google to provide Drive access. Local applications that the operator permits to use the mounted drive can also access files under the operator's Windows account. Existing sharing settings on Google Drive continue to apply.

The setup does not automatically publish files or distribute OAuth tokens to other users. Any future multi-user gateway requires updated disclosures and access controls before use.

This website uses GitHub Pages hosting. GitHub may process technical request information, including IP addresses, under the GitHub Privacy Statement. The site adds no analytics scripts, advertising or application cookies.

6. Revocation, deletion and contact

The account owner can revoke access through their Google Account third-party connections. Revocation stops future authorized access once current credentials no longer work; it does not erase existing Google Drive files, local caches, logs or downloaded copies.

To request removal of locally stored credentials, cache or logs, contact cpong1978@gmail.com. Pending writes should be resolved before cache removal. Files stored in Google Drive can be managed using Google Drive's own deletion controls. The operator may need to verify that a request comes from the relevant account owner.

7. Changes to this policy

The effective date will be updated when this policy changes. Material changes in how Google user data is used will be disclosed, and new consent obtained where required, before the changed use begins.
